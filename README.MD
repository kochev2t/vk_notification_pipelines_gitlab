# VK Notification

Flask-приложение для отправки уведомлений через VK API.

Приложение упаковано в Docker-контейнер. После запуска оно слушает порт `2266` внутри контейнера, который проброшен на порт `2266` сервера.

## Как это работает

1. Docker собирает образ на основе `Dockerfile`.
2. В образ устанавливаются зависимости из `requirements.txt`.
3. Docker Compose создаёт и запускает контейнер `vk_notification`.
4. Приложение `app.py` запускается автоматически.
5. Порт `2266` контейнера становится доступен на хосте как порт `2266`.
6. Для работы с VK API приложение использует access token из переменной окружения `VK_ACCESS_TOKEN`.

## Быстрый запуск

1. Перейдите в папку проекта:

```bash
cd vk_notification
```

2. Соберите образ и запустите контейнер:

```bash
sudo docker compose up -d --build
```

3. Проверьте, что контейнер запущен:

```bash
sudo docker compose ps
```

4. Посмотрите логи приложения:

```bash
sudo docker compose logs -f
```

Чтобы выйти из просмотра логов, нажмите `Ctrl + C`. Контейнер при этом продолжит работать.

## Установка VK Access Token

Приложению необходим access token VK. Он передаётся через переменную окружения `VK_ACCESS_TOKEN`.

### Вариант 1: временно внутри контейнера

Этот способ подходит для быстрой проверки. Переменная будет действовать только в текущей сессии и исчезнет после перезапуска контейнера.

Зайдите в контейнер:

```bash
sudo docker compose exec vk_notification bash
```

Установите токен:

```bash
export VK_ACCESS_TOKEN='ваш_токен'
```

Проверьте переменную:

```bash
echo $VK_ACCESS_TOKEN
```

Запустите приложение:

```bash
python3 app.py
```

Выйдите из контейнера:

```bash
exit
```

### Вариант 2: постоянная настройка

Добавьте токен в `docker-compose.yml`:

```yaml
services:
  vk_notification:
    build: .
    container_name: vk_notification
    restart: unless-stopped
    ports:
      - "2266:2266"
    environment:
      - VK_ACCESS_TOKEN=ваш_токен
```

Затем пересоберите и перезапустите контейнер:

```bash
sudo docker compose up -d --build
```

При таком варианте приложение будет автоматически получать токен при каждом запуске контейнера. Переменные окружения в Compose можно задавать через `environment` либо через `.env`-файл. [22][24]

**Важно:** не публикуйте реальный VK access token в Git, скриншотах или открытых файлах. Для репозитория лучше использовать файл `.env`, который добавлен в `.gitignore`.

## Доступ к приложению

После успешного запуска приложение доступно по адресу:

```text
http://<IP_сервера>:2266
```

На самом сервере:

```text
http://localhost:2266
```

Чтобы приложение было доступно извне контейнера, Flask должен слушать адрес `0.0.0.0`. Например:

```python
app.run(host="0.0.0.0", port=2266)
```

Адрес `127.0.0.1` доступен только внутри самого контейнера и не позволит открыть приложение с сервера или из браузера. [27][29]

## Обновление приложения

Если вы изменили `app.py`, `requirements.txt` или `Dockerfile`, выполните:

```bash
sudo docker compose up -d --build
```

Docker пересоберёт образ и перезапустит контейнер с обновлённым кодом.

## Возможные проблемы

### Порт 2266 уже занят

Проверьте, какой процесс занимает порт:

```bash
sudo lsof -i :2266
```

или:

```bash
sudo ss -ltnp | grep 2266
```

Если порт занят, остановите этот процесс либо измените проброс порта в `docker-compose.yml`.

### Приложение недоступно снаружи

Проверьте:

- контейнер запущен: `sudo docker compose ps`;
- в логах нет ошибок: `sudo docker compose logs -f`;
- Flask слушает `0.0.0.0`, а не `127.0.0.1`;
- порт `2266` открыт в firewall сервера;
- в `docker-compose.yml` указан корректный проброс портов.

### Нужно полностью пересобрать образ

```bash
sudo docker compose down
sudo docker compose build --no-cache
sudo docker compose up -d
```

### Токен не сохраняется после перезапуска

Если токен задавался командой `export` внутри контейнера, он действует только до завершения текущей сессии. Для постоянной работы задайте `VK_ACCESS_TOKEN` в разделе `environment` файла `docker-compose.yml` или используйте `.env`-файл.
